# Teacher LMS: Teaching Studio

Open My Classes, choose Teaching Studio · LMS, or open any assigned class and its Teaching Studio · LMS tab. The first class is selected by the directory shortcut; All classes lets you switch.

Implemented: private saved lesson plans, teaching notes, worksheets, quizzes and examination question papers; generation follows the supplied curriculum language, defaulting to English; editable curriculum excerpts; selection from assigned HOD syllabus units; subject restrictions from published teaching assignments; optimistic version checks; Draft and Reviewed states; private text downloads including answer keys. Generating or saving never publishes work or marks syllabus completion. Resources persist in the application database. Materials belong to a class and subject, with no teaching date, period duration or taught tracking. Existing older resources remain editable. The material editor opens in a spacious modal, full-screen on phones.

Set server-side OPENROUTER_API_KEY and TEACHING_AI_ENABLED=true in .env. Restart the API after configuration changes. Never use NEXT_PUBLIC_ variables for credentials. The LMS uses its own public-curriculum provider path; the older generic AI gateway remains restricted. Personal student records are never retrieved for prompts; entered curriculum text is screened for common identifiers. This screening is conservative, not a guarantee of automatic anonymisation.

Generation uses only openrouter/free, zero prompt/completion price ceilings and data_collection=deny, with no paid-model fallback. Provider/model availability, school request limits (40 attempts per rolling 24 hours, 3 per teacher per minute) and OpenRouter account/provider limits apply. Failed attempts count toward limits. Model selection can vary. A configured key is not a guarantee of available capacity. Prompts are sent to OpenRouter and its selected provider; no claim of a signed school data-processing agreement is made. Logs store request state and selected model, not prompt or output text. A teacher deliberately saves the output to retain it as a resource.

Primary references: [free router](https://openrouter.ai/docs/guides/routing/routers/free-router), [provider routing and price caps](https://openrouter.ai/docs/guides/routing/provider-selection), [reasoning and output budgets](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

The larger TEACHING_STUDIO_PROPOSAL.md remains a roadmap. Source-file ingestion/citation verification, presentations, student practice, automatic Diary/Assignment conversion, question-level mastery and full offline synchronisation are not implemented in this release. Text downloads provide an offline teacher copy.

## Examination papers

Choose Exam question paper, name the paper, select the exam type, add up to 12 topics and choose Easy, Medium, Hard, Hardest or Mixed difficulty. Set objective MCQ count (0-40), subjective count (0-20), and marks per question type. Total questions must be 1-50 and at least the number of topics. Mixed distributes questions evenly across four levels, starting with Easy for any remainder. Each question is assigned a topic round-robin; the returned paper must match the requested question slots. The server checks counts, topic/difficulty labels, duplicate prompts and four-option MCQ answer validity before showing a draft. It cannot certify pedagogical difficulty or factual correctness; teacher review is required. Longer free-model responses can fail capacity/output limits and must be retried.

The full material remains a private teacher copy. Question paper and Answer key text downloads split at the TEACHER ANSWER KEY heading; retain that heading when editing. No exam schedule or question paper is published automatically. Weekly study plan is removed from new creation; older weekly resources open as editable Teaching notes. A single assigned subject is read-only and automatic; teachers with multiple assigned subjects choose only among those published assignments.
